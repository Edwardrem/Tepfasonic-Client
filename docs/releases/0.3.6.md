Hardens dictation against a macOS 26/27 SwiftUI crash.

### Fixed

- **Dictation is far less likely to crash the app on macOS 26/27.** After 0.3.5 fixed the permission crash, some Macs on the macOS 26/27 betas still crashed the moment recording started. The crash is in SwiftUI's own mouse hover hit-testing (`NSViewResponder.platformCurrentEvent`), a use-after-free in the system frameworks that is currently crashing many unrelated apps — no Tepfasonic code appears in the crash. This release removes the things that provoke it: the composer no longer re-renders the conversation while you type or dictate, and the microphone button no longer animates or resizes when recording starts. The app also opts into the pre-Swift-6 executor check, which avoids the exact dereference that faults. If a crash still occurs, it is the underlying system bug; a future macOS update should resolve it.

### For developers

- The composer is now its own `ComposerView` (`App/Tepfasonic/Agent`). `draft`, dictation state and the frequent transcript updates invalidate only that subtree, not `AgentPanelView`, whose transcript is an `NSScrollView`-backed platform view — so a hover hit-test no longer races a responder that SwiftUI rebuilt on a keystroke. The microphone button uses a constant point size and fixed frame and drops `.symbolEffect(.pulse)`.
- `SWIFT_IS_CURRENT_EXECUTOR_LEGACY_MODE_OVERRIDE=legacy` is set in the Info.plist (`LSEnvironment`) and, as a fallback for non-LaunchServices launches, via `setenv` at the top of `TepfasonicApp.init`. It forces the thread-based executor check so `swift_task_isCurrentExecutorWithFlags` does not dereference a stale executor identity (`swift_getObjectType`) on the main thread. Tracked upstream: manaflow-ai/cmux#8952, steipete/CodexBar#2250, my-monkeys/OpenSuperWhisper#107.
