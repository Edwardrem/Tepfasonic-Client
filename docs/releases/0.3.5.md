Fixes the crash when you start dictation in the Claude composer.

### Fixed

- **The microphone no longer crashes the app.** In 0.3.4, tapping the microphone to dictate a message could terminate the app the instant macOS returned the Speech Recognition or Microphone permission decision. Dictation now asks for those permissions without that crash, on this and future macOS releases. If you declined a prompt earlier, grant Speech Recognition and Microphone for Tepfasonic in System Settings › Privacy & Security and the microphone works again.

### For developers

- `SpeechDictation` (`App/Tepfasonic/Agent`) requested Speech and Microphone access from a `@MainActor` async method with `await`. Those TCC completion handlers resume on a background XPC queue, and resuming a main-actor continuation there makes the macOS 26/27 Swift 6 runtime run its executor check (`swift_task_isCurrentExecutorWithFlags`) off the main thread, which now traps (`dispatch_assert_queue_fail`) instead of recovering. The authorization path is now a `nonisolated` helper that uses the plain completion-handler APIs and returns its result to the main actor through `Task { @MainActor in … }`, the same safe hop the recognition-result handler already used. No actor-isolated code runs inside a TCC callback. The behaviour and the on-device transcription are otherwise unchanged.
