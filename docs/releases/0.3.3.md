Check for Updates reaches the feed again, and the site introduces the developer.

### Fixed

- **Check for Updates failed with "The update feed could not be read".** The feed (`appcast.xml` on the project site) was only written when a Sparkle signing key was configured, which it is not yet, so the app fetched a 404 page and tried to parse it. The release workflow now writes the feed on every release: unsigned items with the DMG as the download when no key is set, the signed `generate_appcast` feed when one is. Ad-hoc builds stay download-only (Sparkle cannot install what Gatekeeper would refuse), so the update sheet offers the DMG. A feed that answers with an HTTP error now says so instead of a parse error.

### Added

- The website has an *About the developer* section with links to GitHub and LinkedIn.

### For developers

- `.github/workflows/release.yml`: the *Generate appcast* step merges the new item into the existing feed with a small Python script when `SPARKLE_PRIVATE_KEY` is empty; *Publish appcast to gh-pages* runs unconditionally. `UpdateFeedError` in `UpdateManager` carries the HTTP status.
