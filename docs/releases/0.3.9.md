Caimex as a provider for the chat, and a saved key for each provider.

### New

- **Caimex in the chat.** Settings → Claude → Provider now offers Caimex next to Anthropic and an OpenAI-compatible endpoint. Save a Caimex key, pick a model, and the panel works as before: the same tools, the same per-host approvals and the same audit log. The status line shows a Caimex badge when Caimex answered.
- **A model list from the gateway.** With Caimex selected the Model menu is filled from the gateway's own list of chat models, featured ones first, with a button to refresh it. You can still type a model id by hand. The default is `deepseek-v4-flash`. The agent needs a model with tool calling, and the gateway's list does not say which models support it.
- **Each provider remembers its model.** Switching from Claude to Caimex and back gives you the Claude model you had, not the Caimex one.

### Changed

- **One saved key per provider.** Until now one saved key was shared, and it was sent to whichever provider was selected, including an endpoint you typed. Anthropic, Caimex and the OpenAI-compatible endpoint now each keep their own key in the Keychain, and a key is sent only to its own provider.
- **What happens to the key you already saved.** An Anthropic key (it starts with `sk-ant-`) stays with Claude. Any other saved key stays with the provider that was selected when you update. The other provider asks for its own key the first time you use it. If the OpenAI-compatible endpoint was selected when you update, Tepfasonic looks at the old key once on first launch to tell which kind it is, and macOS may ask for Keychain access at that moment.

### Fixed

- **A model that is not Claude is no longer told it is Claude.** A model reached through Caimex or an OpenAI-compatible endpoint was introduced to itself as "the Claude agent". It is now told which provider it runs on.

### Known limits

- The panel's title and the composer still say "Ask Claude" when Caimex is selected.
- A typed model id is sent as it is: an id the gateway does not know, or a model without tool calling, fails with the gateway's own error.

### For developers

- `LLMProviderConfiguration.Kind.caimex` builds an `OpenAICompatibleProvider` on the fixed base URL `https://api.caimex.ai/v1`. The configuration keeps one model per kind (`models`); a configuration saved by 0.3.8 still decodes.
- `CaimexModelCatalogue` loads `GET /v1/models` without a key, reads at most 4 MB, skips entries it cannot read, and keeps unlocked models whose `capabilities` include `chat` (or that list no capabilities).
- Keychain accounts: `agent.apiKey` (Anthropic, unchanged), `agent.openAICompatible.apiKey`, `agent.caimex.apiKey`. `APIKeyMigration` decides once who owns the 0.3.8 key and records the decision in `agent.keyMigration`; `SecretStore.move(from:to:label:)` renames an item without reading it and never overwrites.
- `ProviderBuildPlan` captures the configuration and the account before the vault prompt, so a provider is always built with the key that belongs to it.
- Debug builds take `--settings-tab=<name>` with `--window=settings` to open Settings on one pane.
